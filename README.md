# Sequential Models for Swahili News Classification

Formative Assignment 2 · *Research-Informed Sequential Models for NLP and Language Technologies*
Dataset: [Zindi – Swahili News Classification Challenge](https://zindi.africa/competitions/swahili-news-classification-challenge)
(5,151 labelled Tanzanian news articles, 5 categories; official metric: multi-class log loss)

**Research question.** *How effectively can sequential models classify Swahili news articles by
category, and what evidence explains the strengths and limitations of each approach, given long
articles, a rich morphology and a severely imbalanced label distribution?*

## Key properties of the data (from `01_eda`)

* **Severe imbalance:** kitaifa 2,000 · michezo 1,720 · biashara 1,360 · kimataifa 54 · burudani 17 (118 : 1).
* **Long sequences:** median ≈ 280 words; 512 words covers ~90% of articles; sub-word tokenisers need more.
* **Rich morphology:** 53% of word types occur once; ~4.7% validation out-of-vocabulary rate.
* **Messy text:** 96% of articles have sentences glued at punctuation ("biashara.Alisema"); labels mix case.
* **Overlapping topics:** national and business news are very similar (TF-IDF centroid cosine 0.91).

## The five approaches

| # | Approach | Sequence handling | Notebook | Owner |
|---|---|---|---|---|
| B1 | TF-IDF (word 1–2 + char 2–5 grams) + logistic regression | none beyond n-grams | `02_baselines` | Member 1 |
| B2 | fastText-style bag of word + bigram embeddings | none (averaged) | `02_baselines` | Member 1 |
| N1 | TextCNN (Kim, 2014) | **local** phrase patterns (3–5-word windows) | `03_textcnn` | Member 3 |
| N2 | BiLSTM/BiGRU + attention | **ordered**, bidirectional, learned word weighting | `04_birnn_attention` | Member 2 |
| N3 | Fine-tuned XLM-R / AfroXLMR / AfriBERTa | **global** self-attention + African-language pretraining | `05_transformer` | Member 4 |

## How to run (Google Colab)

1. **Data:** download `Train.csv`, `Test.csv`, `SampleSubmission.csv` from Zindi and put them in a Google
   Drive folder named **`swahili_news`** (each member, in their own Drive).
2. **Edit `REPO_URL`** in the first code cell of each notebook once and push.
3. **Run order:**
   1. `01_eda` (Member 1) creates `data/splits.csv`. **Commit it before anyone trains.**
   2. `02`–`05` can then run **in parallel**, one member each. Use a **T4 GPU** for 03–05
      (*Runtime → Change runtime type*).
   3. `06_compare_and_error_analysis` runs last, after everyone has pushed `results/` and `experiments/`.
4. **Save outputs:** Colab wipes files when a session ends. The last cell of each notebook copies
   `results/`, `experiments/` and `submissions/` to `MyDrive/swahili_news/outputs/`; upload those folders
   to GitHub (drag-and-drop in the web UI works).

Approximate Colab T4 runtimes: EDA 3 min · baselines 15 min (CPU) · TextCNN 10 min · BiRNN 20 min ·
transformers 60–90 min for all five experiments.

## Reproducibility

* One config (`src/config.py`), one split (`data/splits.csv`), one training loop, one evaluation module.
* Seed 42 for Python/NumPy/PyTorch; deterministic cuDNN.
* Vocabulary, TF-IDF statistics and normalisation are fit on the **training split only**.
* Model selection uses **validation log loss**; the test split is evaluated **once** per approach,
  with 95% bootstrap confidence intervals and paired McNemar tests.
* Every run is logged (hypothesis, motivation, configuration, metrics, time, parameter count) in
  `experiments/log_<model>.csv`.
